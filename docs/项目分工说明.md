# 🎯 智能旅游平台 - 项目分工说明

## 📋 模块划分 (4人分工)

| 模块 | 负责人 | 主要功能 | 前端目录 |
|------|--------|----------|----------|
| **模块A: 用户认证** | 成员1 | 登录、注册、个人中心、JWT认证 | `src/modules/auth/` |
| **模块B: 景点管理** | 成员2 | 景点列表、详情、搜索、地区管理 | `src/modules/spot/` |
| **模块C: 智能推荐** | 成员3 | 智能推荐算法、路线规划、费用预估、地图展示 | `src/modules/recommend/` |
| **模块D: 订单社交** | 成员4 | 预订管理、评论、收藏、分享 | `src/modules/order/` |

---

## ⚠️ 重要：代码隔离原则

**每个成员只在自己的模块目录下开发，避免代码冲突！**

```
frontend/src/modules/

├── recommend/      # 🎯 成员3 专属目录

```

## 🚫 避免冲突的规则

### 1. 只修改自己模块的文件
```
✅ 正确: 成员1 修改 src/pages/Login.vue 或 src/modules/auth/api/index.ts
❌ 错误: 成员1 修改 src/pages/Spots.vue (属于成员2)
```

### 2. 添加路由在自己模块的 routes.ts
```
✅ 正确: 在 src/modules/auth/routes.ts 添加新路由
❌ 错误: 直接修改 src/router/index.ts
```

### 3. 模块间通信使用 Store 或 Props
```typescript
// 如果需要用户信息，导入 auth 模块的 store
import { useAuthStore } from '@/modules/auth/store';
const authStore = useAuthStore();
console.log(authStore.user);
```

### 4. 公共组件放在 src/components/
如果某个组件需要多个模块使用，放到公共目录并通知团队。
